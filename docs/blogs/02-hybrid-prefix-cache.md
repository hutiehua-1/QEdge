# 多模态混合模型的前缀缓存：为什么只恢复 KV 不够

> 摘要：前缀复用通常被理解成复用相同 token 的 KV。对于同时包含 Full Attention 与 Gated DeltaNet 的多模态模型，还必须恢复同一边界上的递归、卷积及位置相关状态，并区分不同图片。本文结合 QEdge 的状态管理实现讨论这些约束。
>
> 状态：实现解读初稿；完整前缀缓存默认关闭，系统前缀缓存默认开启。本文不宣称已获得设备上的独立加速收益。

## 相同 token 并不一定代表相同历史

两个请求可以具有相同的提问模板和图片占位 token，但图片内容不同。若仅根据 token ID 查缓存，系统可能把一张图片的历史错用于另一张图片。错误不一定表现为异常，而可能表现为一个格式正常、内容错误的答案。

QEdge 的 `multimodal_cache_key` 把媒体内容纳入身份：PIL 路径规范化成 RGB，哈希尺寸和像素；张量路径加入形状、dtype 与字节内容；还把网格及处理配置元数据加入哈希。不同输入表示的 key 不保证彼此相等，应固定处理路径。

内容 key 只是一个组成部分。模型权重、Processor 配置和位置语义同样决定历史是否可复用；本项目缓存是运行中的局部状态，不应把它当作跨模型通用的持久化缓存格式。

## 媒体依赖从哪里开始

所有块都加入图片哈希会很保守，却也会阻止图片之前的稳定文本共享。QEdge 根据 Processor 的媒体 token 范围，只给相交的块加入媒体标识。

块哈希是链式计算的：当前块结合自己的 token、前一块的 hash 和媒体附加 key。这样，图片之前的独立文本块仍可匹配，图片所在块会区分内容，后续块通过 parent hash 继承图片依赖。

```text
稳定文本块       图片相交块         后续问题块
H(text)    → H(tokens, image-A) → H(tokens, previous)
           → H(tokens, image-B) → H(tokens, previous)
```

附加 key 带长度信息，避免把不同字符串拼接组合视为同一输入。哈希碰撞保护及身份域仍需结合威胁模型讨论；不能仅凭使用哈希就承诺零误用。

## 混合模型还缺哪些状态

普通 Full Attention 的前缀可以用历史 K/V 表示。Gated DeltaNet 则有递归状态，卷积还依赖窗口历史。多模态位置编码又引入位置相关状态。

如果恢复第 N 个 token 的 KV，却拿第 M 个 token 的递归状态继续执行，张量形状可能全部合法，但计算已经不再对应同一个历史。因此，可恢复的前缀必须是几类状态共同拥有的边界。

QEdge 在块元数据中保存 `hybrid_snapshot` 与 `rope_delta_snapshot`，在执行前恢复。前缀分配会回退到具有可恢复混合快照的命中边界，而不是简单拿最长 token 命中直接继续。

## 短系统前缀与整页的矛盾

当前物理块默认大小为 256 token，而固定任务说明通常不足一页。如果只复用整页，这段稳定前缀未必能获得收益。

代码提供部分前缀的独立发布与恢复路径，避免为了对齐页边界向 prompt 填充内容。系统说明被前移到图片之前时，可以形成不依赖图片的短前缀；剩余的图片和动态问题分别处理。这也意味着需要把消息变化带来的质量影响单独验证。

## 为什么实现了完整缓存却默认关闭

混合快照不是免费的。创建、复制与管理状态可能抵消复用的收益，尤其在图片和问题基本不重复的工作负载上。

项目实现了稀疏快照和自适应准入：低命中窗口下减少普通 miss 的快照开销，并周期性探测负载是否变化。当前 `prefix_snapshot_interval_blocks=32`，应按代码值理解，不能沿用旧注释中“每 4 块”的描述。

这些机制存在不代表任何负载都会获益。`enable_prefix_caching=False` 与 `enable_system_prefix_caching=True` 是当前默认组合。写实验报告时应列出实际开关、命中率、快照开销和答案一致性。

## 如何验证这条路径

主机测试可验证页引用计数、淘汰通知、媒体相交边界和链式哈希传播。设备验证还应对比缓存开启/关闭时同一请求的输出，并覆盖：相同文字不同图片、部分命中、恢复边界、页淘汰后重新分配、不同输入长度和工作负载切换。

本文提供的是实现思路与验证清单，没有用主机测试代替上述设备证据。
