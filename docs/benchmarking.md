# 评测与复现

## 真实运行

使用 README 中 `--backend transformers` 的命令。两份公开开发集分别运行，保持模型、依赖、样本数、seed、预热、生成参数和顺序一致。不要修改正式评测解析与计分规则来提高成绩。

入口参数来自 `benchmark_public.py`：`--dataset-path`、`--model-path`、`--output`、`--num-samples`、`--seed`、`--backend`、`--device`、`--warmup-samples`。默认 seed 为 20260625，预热 2 条；固定生成参数为 `max_new_tokens=256, temperature=0, top_p=1`。`--device` 虽接受字符串，真实 wrapper 只接受 `auto` 或 `cuda`。

## 指标含义

- 准确率是公开答案提取器得到的选项与标注匹配的比例。
- TTFT 取 wrapper 的计时值；文本 streamer 的首次非空文本事件与设备首次 token 产生不一定相同，必须沿用同一计时路径比较。
- 单样本吞吐由 `(max(token_count - 1, 1)) / max(elapsed_seconds - max(ttft_seconds, 0), 1e-6)` 计算（无 token 或无有效时间返回 0）。报告取有效正值的算术平均，**不是所有样本 token 数除以总运行时间**。
- 总基准耗时还包括预热、缓存清理等，不可直接用平均样本吞吐推断端到端服务吞吐。
- 输出规范化、prompt 角色/顺序调整可能影响答案；须与算子收益分开分析。

## 历史结果

`results/v1-historical-summary.json` 保存随包结果的非敏感汇总、结果原文件 SHA256 与重算信息。原始 JSON 有 2000 条、1613 正确，准确率 0.8065；按已序列化记录重算的平均 TTFT 60.449 ms、平均吞吐 680.489 tokens/s，校验错误样本为 0。

这只验证结果文件内部一致性，没有验证其硬件真实性、当前代码可复现性或与 baseline 的可比性。软件版本、硬件、模型 revision 缺失。记录中的绝对数据路径与逐样本答案不随本仓库发布。

## 消融建议

先固定环境与数据，再逐项开关并保存完整配置。建议比较系统前缀缓存、完整前缀缓存、融合 Norm/MRoPE/KV、图执行与 FLA Prefill。不能把关闭一个逻辑开关当作移除了所有相关依赖；也不能在相同会话中让不同实验共享未清理的历史状态。

每轮至少记录正确数、TTFT 的均值/分位数、样本级吞吐、端到端耗时、显存、初始化时间与错误数。当前默认评测不自动给出全部分位数；后处理时明确方法。未跑的表格留空，不填预计收益。
